# Code of Conduct

DataSentry is an open-source engineering project. Discussions should remain useful to people trying to build, test, review, and operate the software.

## Expected behavior

Participants are expected to:

- discuss ideas and code on their technical merits;
- provide reproducible evidence when making factual or performance claims;
- give specific, actionable review feedback;
- assume good faith while still challenging weak assumptions;
- respect different levels of experience and different technical backgrounds;
- keep bug reports, issues, pull requests, and Discussions focused on the project;
- protect private data, credentials, and security-sensitive information.

## Unacceptable behavior

The following is not acceptable:

- harassment, threats, discriminatory language, or personal attacks;
- sexualized or deliberately humiliating comments;
- sustained disruption, spam, or bad-faith derailment;
- publishing another person's private information without permission;
- deliberately exposing secrets, customer data, or vulnerability details in public channels;
- using project spaces primarily for unrelated promotion.

## Technical disagreement

Strong technical disagreement is welcome. Prefer statements such as:

- “This benchmark does not control for X; here is a reproduction.”
- “This repair operation violates the source-overwrite invariant.”
- “I think this API should remain smaller because…”

Avoid turning disagreement about code into claims about a contributor's competence or motives.

## Enforcement

Maintainers may edit, hide, lock, or remove content that violates this policy and may restrict participation for repeated or severe violations.

For conduct concerns that should not be handled publicly, use the repository's available private contact/reporting mechanisms. Security vulnerabilities should follow [`SECURITY.md`](SECURITY.md), not the ordinary conduct-reporting path.

## Scope

This policy applies to DataSentry repository spaces and to project-related interactions where someone is representing the project or its community.
