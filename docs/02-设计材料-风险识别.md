# DataSentry AI — 设计材料 02：风险识别报告

> 依据《Prompt 完整版 v2.0》全文，从 **过度设计**、**技术风险**、**隐私风险** 三个维度识别风险，
> 每条给出：风险等级、触发条件、影响、缓解措施。风险编号与 01 一致性检查中的 C 编号交叉引用。
> 等级：🔴 高（可能致命）/ 🟡 中（可能延误）/ 🟢 低（可接受）

---

## 一、过度设计风险（Over-Engineering）

### R-OD-01 🔴 功能面过宽：17 项目标 + 55 章规格，远超单人/双人 12 周可交付

- **来源**：三（项目目标 19 项能力）；七（MVP 六数据源 + 四交互 + 12 类核心能力）
- **触发条件**：试图在 MVP 期全量实现「四十三、最终任务」15 项内容 + 四十五 30 个 Issue
- **影响**：每项都做一点、每项都未达标；验收标准（四十二）无法满足；演示剧本（三十四）走不通
- **缓解**：
  1. 严格执行第 3 项（MVP/V1 划分），MVP 只保「导入→扫描→Issue→报告→CLI/SDK」闭环；
  2. 以 3.1 的 6 个 KPI 为 MVP 硬性验收，其余能力一律排 V1；
  3. 每周 DoD（42.1）未过不进下一步（41 章「8 步法」本身就是门禁）

### R-OD-02 🟡 双执行引擎（DuckDB + Polars）可能过度设计

- **来源**：17.1 同时推荐 DuckDB 与 Polars；20.2 五级执行策略
- **触发条件**：为「SQL pushdown」与「DataFrame 计算」分别维护两套执行抽象
- **影响**：工作量翻倍；两者边界模糊导致行为不一致；测试矩阵爆炸
- **缓解**：MVP 以 **DuckDB 为唯一执行引擎**（同时提供 sql 与 dataframe 两种调用面，
  DuckDB 本身可替代 pandas 路径）；Polars 留作 V1 优化选项，在 ADR 记录

### R-OD-03 🟡 论文研究设计前置风险

- **来源**：三十（30.1~30.8 完整 Benchmark + RQ1~RQ3 + 消融矩阵）
- **触发条件**：把论文实验（5 seeds × 7 组消融 × 多基线工具对比）当作 MVP 交付物
- **影响**：研究目标挤占产品闭环时间；基线工具（GE/Soda/Evidently）对比本身是独立工程
- **缓解**：
  1. DQBench v0.1 只做「合成数据 + Ground Truth + Precision/Recall/F1」最小集（34 章 demo 数据集即可承载）；
  2. 基线对比、消融矩阵、论文写作全部归 Phase 6（30.8 目标定位为 arXiv + 后续会议投递）；
  3. RQ 设计保留在文档（30.8），数据收集依赖 DQBench 逐步扩展，不设硬期限

### R-OD-04 🟢 全量检测器族一次性实现

- **来源**：十一（11.3~11.12 约 70+ 检测器）
- **触发条件**：MVP 期实现全部检测器
- **缓解**：按第 3 项划分——MVP 只实现 20~25 个高价值检测器（映射 11.3/11.4/11.5 稳健组/
  11.7 核心/11.9 一二级），Isolation Forest/LOF/跨表/漂移全部 V1

### R-OD-05 🟢 插件系统、反馈学习、多语言 UI 等「生态能力」前置

- **来源**：三十二（插件）、三十一（反馈学习）、五十（i18n 中英双语）
- **缓解**：全部归 V1+；MVP UI 仅中文（或英文单语），i18n 资源文件结构预留但只填一种语言

## 二、技术风险（Technical Risks）

### R-TECH-01 🔴 100 万行性能目标与 DuckDB 选择存在验证风险

- **来源**：3.1（画像 ≤ 60s @1e6）、20.4 预算表、C-05
- **触发条件**：模糊重复（11.9 三级）、LOF/Isolation Forest（11.5）在 1e6 行上的性能不达预期
- **影响**：KPI 不达标 → 验收失败
- **缓解**：
  1. 第 2 周就搭性能基准脚本（`benchmarks/`），每周回归（37.5 Stage 7）；
  2. 模糊重复强制 blocking + 抽样（11.9 已有要求），1e7 场景仅抽样路径；
  3. 对 1e6 行做「采样 + 全量统计分离」设计（20.3），报告中明确哪些指标基于样本

### R-TECH-02 🔴 LLM 无 Key 降级路径若未打通，MVP 不可演示

- **来源**：13.6 降级链、39.1「无 API Key 可用」、3.1「无 LLM 完整可用性 100%」
- **触发条件**：AI 解释/语义推断代码路径与 LLMProvider 强耦合；Mock/None Provider 未覆盖全部调用点
- **影响**：离线场景功能崩溃；演示剧本第 12 镜头（关掉 LLM 重扫）失败
- **缓解**：
  1. 所有 AI 入口经 `LLMProviderManager`（13.6），业务代码禁止直调 Provider；
  2. Mock Provider 作为测试标配（29.6），None Provider 冒烟测试纳入 CI；
  3. 8 步法每步测试必须包含「无 LLM 配置」运行用例

### R-TECH-03 🟡 证据融合与 Issue 聚类算法的复杂度不可低估

- **来源**：12.7 融合算法（聚类键含 affected_row_key）
- **触发条件**：1e6 行 × 70 检测器候选 → 融合阶段的聚类计算量；行级合并的内存占用
- **影响**：融合成为瓶颈或内存溢出
- **缓解**：
  1. 融合按 (issue_family, columns) 先做列级聚合，行级证据只在确有行级定位时物化（12.7 已有「仅携带行级证据时才合并行级」约束）；
  2. 融合引擎做流式/分块实现；基准脚本覆盖融合阶段耗时

### R-TECH-04 🟡 XLSX/PostgreSQL 连接器的安全实现细节多

- **来源**：28.3（Excel 宏/外部链接）、49.2（PG 只读护栏）
- **触发条件**：openpyxl 读取含宏/外部链接文件；PG 查询护栏被绕过
- **影响**：安全测试（29.4）不过；PG 只读约束失效
- **缓解**：openpyxl `read_only=True` + 显式禁用宏执行（openpyxl 本身不执行宏，需测试锁定）；
  PG 连接串强制 `options=-c default_transaction_read_only=on`（28.7 已有），
  语句白名单在代理层强制（49.2）

### R-TECH-05 🟡 报告/UI 大表渲染性能

- **来源**：21.8（虚拟滚动）、42.1 W8 E2E
- **触发条件**：1e6 行数据集 Issue 表/受影响行表渲染卡顿
- **缓解**：服务端分页 + TanStack Table 虚拟滚动；受影响行默认只加载前 1000 行 + 导出完整集

### R-TECH-06 🟡 Python 3.12/3.13 + 依赖版本矩阵（DuckDB/Polars/PyArrow 迭代快）

- **触发条件**：依赖 API 变动导致锁版本困难；3.13 兼容问题
- **缓解**：uv.lock 锁全量依赖；CI 三平台冒烟（29.6）；3.13 仅冒烟不承诺全绿

### R-TECH-07 🟢 SQLite 并发写限制

- **来源**：15.8（同一时刻仅一个 repair run）、24.1（Job 持久化）
- **影响**：并发场景 WAL 下仍有写锁
- **缓解**：单写入者队列（进程内 asyncio 锁即可，MVP 无多进程写需求）；如出现多进程，
  使用 SQLite WAL + busy_timeout；不引入 Redis（17.3 已约束）

## 三、隐私风险（Privacy Risks）

### R-PRI-01 🔴 脱敏管线一旦有遗漏，PII 即外发 LLM

- **来源**：13.3/13.4 脱敏表；4.1 边界；28.6 威胁模型第一行
- **触发条件**：新增 Prompt 任务类型时未走 `LLMContextBuilder`；自由文本截断 200 字符仍含 PII；
  掩码策略被用户配置放宽到不安全值
- **影响**：违反核心承诺，项目信誉灾难
- **缓解**：
  1. **强制路由**：所有 LLM 输入必须经 `LLMContextBuilder.build()`（13.3），架构上禁止旁路；
  2. 脱敏函数独立成包并做属性测试（任意输入不输出原始 PII 子串，29.2 扩展）；
  3. 掩码策略可配置范围设下限（如自由文本截断长度 ≤ 200 不可放宽）；
  4. 29.4 安全测试 + 30.8 伦理章节披露

### R-PRI-02 🟡 掩码可配置项过多导致「配置错误即泄露」

- **来源**：13.4「掩码策略可配置，但默认值必须满足上述要求」
- **缓解**：提供 `safe`/`balanced`/`permissive` 三档预设，UI 中 permissive 档强制红色警告 +
  二次确认；日志记录档位变更（AuditEvent 复用）

### R-PRI-03 🟡 数据库凭据泄露（连接串入日志/元数据）

- **来源**：49.2、28.6 第二行
- **缓解**：连接串统一经 `credential_redactor` 脱敏后再写入任何存储；日志过滤器
  （structlog processor）全局拦截；gitleaks 进 pre-commit 与 CI（28.7）

### R-PRI-04 🟢 报告/导出二次泄露

- **来源**：26 报告系统、28.6「报告导出」
- **缓解**：报告默认脱敏（52.1），`--no-mask` 需显式 + 警告；SARIF/JUnit 导出同样遵循；
  导出前二次确认对话框

### R-PRI-05 🟢 LLM 缓存文件中残留敏感信息

- **来源**：53.1（缓存脱敏内容哈希 + 响应）
- **缓解**：缓存键=掩码后哈希（53.1 已有），缓存表权限 600，保留 7 天可配，删除项目级联清缓存
