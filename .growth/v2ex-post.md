# V2EX 求反馈帖（中文）

节点：程序员
标题建议：**用统计做检测、用 LLM 做建议的开源数据质量工具，想听听大家的意见**

---

写了一个开源的数据质量工具，想在发布前听听大家的看法。不推销，只求反馈——尤其是"你们实际工作中到底怎么处理数据质量"这个问题的答案。

背景：我做了 39 个统计检测器（缺失、日期、编码、跨字段规则、外键、精确+模糊重复、Isolation Forest/LOF 离群），扫描后每个问题带证据链：样本、占比、置信度。六维质量评分。修复走"提议 → 预览 → 应用（带指纹+回滚）→ 回滚"的人工审批闭环。LLM 可选：自然语言生成规则候选（带预演）、AI 修复建议，但**只有人批准才生效**；不配 LLM 也全功能可用。带一个 MCP server（20 个工具），Claude 可以直接跑真实检查。数据不出机器（可接本地 Ollama），DuckDB 执行引擎。

用法就三条命令：

```bash
pip install datasentry-ai
datasentry scan orders.csv
datasentry issues list --severity high
```

GitHub：https://github.com/Jackxiaozhiren/datasentry （Apache-2.0，约 1200 个测试，覆盖率 95%）

想请教三个问题：

1. 你们团队现在做数据质量检查吗？用什么工具，还是纯靠人肉看？
2. "AI 只建议、人决定"这个闭环，在你们的工作流里是加分还是摩擦？
3. 你第一个想查的检测器是什么？我留了插件 API，加自定义检测器不难。

任何批评都欢迎，尤其是"这个想法哪里不对"。
